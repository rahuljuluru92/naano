## Deploying to Vercel

1. **Push to GitHub** — there's no remote configured yet:
```bash
git remote add origin <your-github-repo-url>
git push -u origin main
```

2. **Import into Vercel** — [vercel.com/new](https://vercel.com/new) → import that GitHub repo. It auto-detects Next.js; no build config needed.

3. **Set environment variables** in the Vercel project (Settings → Environment Variables) — only two, from your `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   
   Skip `SUPABASE_SERVICE_ROLE_KEY` — I checked, and nothing under `src/` imports `lib/supabase/admin.ts`; it's only ever used by the local seed scripts, so there's no reason to expose that secret to the deployed app.

4. **Update Supabase's allowed URLs** — easy to miss, breaks auth silently if skipped. In the Supabase dashboard → Authentication → URL Configuration:
   - Set **Site URL** to your Vercel production URL
   - Add that same URL (and `https://*.vercel.app` if you want preview deploys to work too) to **Redirect URLs** — this is what `src/app/auth/callback/route.ts` needs to complete email confirmation.

5. **Deploy**, then verify in an incognito window per your own `PLAN.md` checklist: click every nav/footer link, sign in as one of the seed brands/creators, and confirm `/dashboard/pipeline` and `/dashboard/campaigns/*/matches` show the seeded data.
